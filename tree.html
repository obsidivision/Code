Unit 05

Tree 트리

A tree is a graph with no cycles and a designated starting point. That single restriction buys you a hierarchy — and, once you add an ordering rule, searching in O(log n).

On this page Binary trees Special shapes Two representations The three traversals Expression trees Binary search trees Practice problems

Binary trees

The definition is recursive, and it is worth reading twice because every algorithm on this page is just the definition turned into code:

A binary tree is either empty, or it is a root node together with two binary trees — its left subtree and its right subtree.

"Empty" is a real binary tree, not a special case to patch later. That is why every function below starts with if node is None.

Consequences of that definition:

  • Every node has at most two children — degree ≤ 2.
  • Left and right are distinguishable. A root with one left child is a different tree from a root with one right child, even though both have two nodes.
  • Every node except the root has exactly one parent, so an n-node tree has exactly n − 1 edges — one edge per node, minus the root which has none above it.
  • There are no cycles, so there is exactly one path from the root to any node.

6 nodes, 5 edges, height 3

Special shapes and height limits

Full / perfect · 포화 이진 트리Every level is completely filled. A perfect tree of height h holds exactly 2h − 1 nodes, and level k holds 2k−1 of them.
Complete · 완전 이진 트리Every level is filled except possibly the last, and the last fills strictly left to right with no gaps. This is the shape that stores perfectly in an array.
Skewed · 편향 이진 트리Every node has only one child, so the tree degenerates into a linked list. This is the worst case that ruins a BST's performance.

For n nodes, the minimum possible height is ⌈log₂(n + 1)⌉ — achieved when the tree is as bushy as possible — and the maximum is n, when the tree is a single skewed chain. The whole promise of tree-based searching rests on staying near the minimum.

tree_node.py
class TreeNode:
    def __init__(self, data, left=None, right=None):
        self.data = data
        self.left = left          # a TreeNode, or None
        self.right = right        # a TreeNode, or None


#        8
#      /   \
#     3     10
#    / \      \
#   1   6      14
root = TreeNode(8,
                TreeNode(3, TreeNode(1), TreeNode(6)),
                TreeNode(10, None, TreeNode(14)))


def height(node):
    """Number of levels. An empty tree has height 0 - straight from the definition."""
    if node is None:
        return 0
    return 1 + max(height(node.left), height(node.right))


def count(node):
    if node is None:
        return 0
    return 1 + count(node.left) + count(node.right)


print(count(root), height(root))      # 6 3

Two representations

Array-based

Number the nodes level by level, left to right, starting at 1, and store each node at that index. Then the structure is pure arithmetic — no pointers at all:

Parent of ii // 2
Left child of i2 * i
Right child of i2 * i + 1
array_tree.py
# 1-indexed array representation; index 0 is left unused so the arithmetic stays clean.
tree = [None, 8, 3, 10, 1, 6, None, 14]
#              1  2   3  4  5     6   7

def parent(i):      return i // 2
def left_child(i):  return 2 * i
def right_child(i): return 2 * i + 1

print(tree[left_child(2)], tree[right_child(2)])   # 1 6   (children of the node holding 3)
print(tree[parent(5)])                             # 3     (parent of the node holding 6)

Compact and fast for a complete tree — this is exactly how heaps are stored. For a sparse or skewed tree it is terrible: a skewed tree of 10 nodes needs an array of 2¹⁰ slots, nearly all empty.

Linked

Each node is an object holding data, left and right — the TreeNode class above. Memory is proportional to the number of real nodes regardless of shape, and inserting does not require resizing anything. This is what almost all real code uses, and what every judge problem below hands you.

The three traversals

A list has one obvious order. A tree does not, so you pick one. All three traversals visit the left subtree before the right; they differ only in when the node itself is visited.

Preorder · 전위 (VLR)Node first, then left, then right. Use it to copy a tree or to print a structure top-down.
Inorder · 중위 (LVR)Left, node, right. On a BST this emits the keys in sorted order.
Postorder · 후위 (LRV)Both children first, node last. Use it whenever a node's result depends on its children — evaluating, or freeing memory.
traversals.py
def preorder(node, out=None):
    """VLR - visit the node, then the left subtree, then the right."""
    if out is None:
        out = []
    if node is not None:
        out.append(node.data)          # V
        preorder(node.left, out)       # L
        preorder(node.right, out)      # R
    return out


def inorder(node, out=None):
    """LVR - on a binary search tree this comes out sorted."""
    if out is None:
        out = []
    if node is not None:
        inorder(node.left, out)        # L
        out.append(node.data)          # V
        inorder(node.right, out)       # R
    return out


def postorder(node, out=None):
    """LRV - both children are finished before the node itself is visited."""
    if out is None:
        out = []
    if node is not None:
        postorder(node.left, out)      # L
        postorder(node.right, out)     # R
        out.append(node.data)          # V
    return out


print(preorder(root))    # [8, 3, 1, 6, 10, 14]
print(inorder(root))     # [1, 3, 6, 8, 10, 14]   <- sorted, because this is a BST
print(postorder(root))   # [1, 6, 3, 14, 10, 8]

Reading trick: the letter V tells you where the node goes. Pre = V first, In = V in the middle, Post = V last. L always comes before R.

Expression trees

An expression tree stores an arithmetic expression as a tree: operators at the internal nodes, operands at the leaves. The tree below is 4 * (5 - (7 + 2)).

Postfix: 4 5 7 2 + - *  ·  value: −16

The structure encodes precedence and grouping, so no brackets are needed — the shape of the tree already says that 7 + 2 happens before the subtraction. Run the three traversals over it and you get the three classic notations: inorder gives infix, preorder gives prefix, postorder gives postfix.

Why evaluation is postorder: an operator cannot run until both of its operands have values. Postorder finishes both subtrees before visiting the node, which is exactly that requirement. Try to evaluate in preorder and you reach * while neither side is known yet.

Building the tree from postfix input uses a stack — the same structure from Unit 03. Read tokens left to right: an operand becomes a leaf and is pushed; an operator pops the two most recent subtrees, becomes their parent, and is pushed back. Pop the two in reverse order, or subtraction and division come out backwards.

expression_tree.py
import operator

OPERATORS = {"+": operator.add, "-": operator.sub,
             "*": operator.mul, "/": operator.truediv}


def build_from_postfix(tokens):
    """Build an expression tree from postfix tokens, using a stack of subtrees."""
    stack = []
    for token in tokens:
        if token in OPERATORS:
            right = stack.pop()            # popped in reverse: the second operand comes off first
            left = stack.pop()
            stack.append(TreeNode(token, left, right))
        else:
            stack.append(TreeNode(float(token)))
    return stack.pop()                     # exactly one subtree is left: the root


def evaluate(node):
    """Postorder evaluation: both operands must be known before the operator runs."""
    if node.left is None and node.right is None:
        return node.data                   # a leaf is an operand
    return OPERATORS[node.data](evaluate(node.left), evaluate(node.right))


tree = build_from_postfix(["4", "5", "7", "2", "+", "-", "*"])
print(inorder(tree))    # [4.0, '*', 5.0, '-', 7.0, '+', 2.0]  - infix, minus the brackets
print(evaluate(tree))   # -16.0    which is 4 * (5 - (7 + 2))

Binary search trees

A BST adds one ordering rule to the binary tree, and the rule applies to whole subtrees, not just to the immediate children:

For every node: every key in its left subtree is smaller, and every key in its right subtree is larger.

That recursion is the part people get wrong. A node's right child being larger is not enough — a value buried three levels down the right subtree must be larger than the node too.

The payoff: at every node one comparison eliminates an entire subtree. On a balanced tree that is O(log n) for search, insert and delete. On a skewed tree it degrades to O(n) — the tree has become a linked list. (Self-balancing variants such as AVL and red-black trees exist to prevent exactly that.)

Also worth memorising: an inorder traversal of a BST prints the keys in sorted order.

Search

Compare with the current node. Equal → found. Smaller → go left. Larger → go right. Hit None → the key is not in the tree.

Insert

Search for the key. The search will fail, and the None it fails at is precisely the spot the key belongs in — attach the new leaf there. Inserting never restructures an existing node.

Delete — three cases

  1. Leaf node. No children to rescue. Unlink it from its parent and you are done.
  2. One child. Splice that child up into the deleted node's place. The whole subtree keeps its ordering relative to everything above.
  3. Two children. You cannot simply remove it — two subtrees would be orphaned. Instead find the node's in-order successor: the smallest key in its right subtree (equivalently, use the largest key in the left subtree). Copy that value into the node, then delete the successor from the right subtree. The successor is the leftmost node of that subtree, so it has no left child — meaning that second deletion is guaranteed to be case 1 or case 2, and the recursion terminates.

Why the successor specifically? It is the next key in sorted order, so it is larger than everything in the left subtree and smaller than everything else in the right subtree. It is the only value that can sit in that position without breaking the BST rule.

bst.py
def bst_search(node, key):
    """Iterative search - one comparison decides the whole direction."""
    while node is not None:
        if key == node.data:
            return node
        node = node.left if key < node.data else node.right
    return None                            # fell off the tree: not present


def bst_insert(node, key):
    """Insert exactly where a failed search would have stopped. Returns the subtree root."""
    if node is None:
        return TreeNode(key)               # this is where the search ran out
    if key < node.data:
        node.left = bst_insert(node.left, key)
    elif key > node.data:
        node.right = bst_insert(node.right, key)
    return node                            # key == node.data -> duplicate, ignored


def bst_min(node):
    while node.left is not None:           # smallest key = leftmost node
        node = node.left
    return node


def bst_delete(node, key):
    """Delete `key` and return the new subtree root."""
    if node is None:
        return None
    if key < node.data:
        node.left = bst_delete(node.left, key)
    elif key > node.data:
        node.right = bst_delete(node.right, key)
    else:
        # case (a) leaf, and case (b) one child, collapse into these two lines:
        if node.left is None:
            return node.right              # None for a leaf, else splice the right child up
        if node.right is None:
            return node.left
        # case (c) two children: copy the in-order successor's value, then delete it below
        successor = bst_min(node.right)
        node.data = successor.data
        node.right = bst_delete(node.right, successor.data)
    return node


tree = None
for key in [8, 3, 10, 1, 6, 14, 4, 7]:
    tree = bst_insert(tree, key)
print(inorder(tree))                       # [1, 3, 4, 6, 7, 8, 10, 14]
print(bst_search(tree, 6) is not None)     # True
tree = bst_delete(tree, 3)                 # two children -> replaced by successor 4
print(inorder(tree))                       # [1, 4, 6, 7, 8, 10, 14]
