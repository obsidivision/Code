Sorting 정렬

Putting data in order is the first algorithm most courses teach, because almost everything else gets easier once the data is sorted. Start with the two quadratic sorts you can trace by hand.

Why sort at all

Sorting is rearranging a collection so its items sit in a defined order — smallest to largest, alphabetically, by date, by whatever key you choose. It is rarely the goal by itself. It is what you do first so that the next step gets cheap:

  • Searching. Finding a value in unordered data means checking everything, O(n). Once it is sorted you can binary-search it in O(log n).
  • Spotting structure. Duplicates sit next to each other, the minimum and maximum are at the ends, and the median is in the middle.
  • Merging and comparing. Two sorted lists can be combined in one linear pass; two unsorted ones cannot.

Bubble sort and selection sort are both O(n²), so nobody ships them for large inputs. You learn them because they are short enough to trace on paper, and tracing them is what teaches you to reason about loop invariants — "after pass k, what do I know for certain?"

Bubble sort

Walk along the array comparing each item with the one directly to its right. If the pair is out of order, swap it. One walk from left to right is called a pass.

The key observation: during a pass, the largest value you meet keeps getting swapped rightward and never stops, so by the end of the pass it is sitting in the last slot — its final position. The largest unsorted value "bubbles" to the end every pass. Repeat, and each pass can stop one slot earlier than the last one. After at most n − 1 passes everything is in place.

SwapsUp to O(n²) — many small adjacent swaps
Extra memoryO(1) — sorts in place
Stable?Yes, if you only swap on a strict >
bubble_sort.py
def bubble_sort(values):
    """Sort `values` in place with bubble sort. Returns the same list."""
    n = len(values)
    for done in range(n - 1):              # n-1 passes is always enough
        swapped = False
        # after `done` passes the last `done` slots already hold the biggest values,
        # so each pass can stop a little earlier than the previous one
        for i in range(n - 1 - done):
            if values[i] > values[i + 1]:  # strict > keeps equal items in order -> stable
                values[i], values[i + 1] = values[i + 1], values[i]
                swapped = True
        if not swapped:                    # a clean pass means it is already sorted
            break                          # best case becomes O(n)
    return values


print(bubble_sort([5, 4, 3, 2, 1]))        # [1, 2, 3, 4, 5]
The early-exit flag matters.

If a whole pass makes zero swaps, every adjacent pair is already in order — which means the entire array is sorted, and you can stop. That is what turns the best case into a single O(n) pass. Without the flag, bubble sort is O(n²) even on data that was already sorted.

Selection sort

Different strategy, same quadratic cost. Treat the array as a sorted prefix (empty at the start) and an unsorted remainder. Each pass scans the whole remainder, finds the smallest value in it, and swaps that value into the first slot of the remainder. The sorted prefix grows by one, left to right.

Notice what the inner loop does: it only tracks the index of the smallest value found so far. Nothing moves until the scan is finished, and then at most one swap happens. That is the real difference from bubble sort — same number of comparisons, far fewer writes.

TimeO(n²) always — no best case, the scan never shortens
SwapsAt most n − 1 — one per pass
Extra memoryO(1) — sorts in place
Stable?No — a long-distance swap can jump equal items past each other
selection_sort.py
def selection_sort(values):
    """Sort `values` in place with selection sort. Returns the same list."""
    n = len(values)
    for start in range(n - 1):
        lowest = start
        for i in range(start + 1, n):      # scan the unsorted remainder
            if values[i] < values[lowest]:
                lowest = i                 # remember *where* the minimum is, do not swap yet
        if lowest != start:
            values[start], values[lowest] = values[lowest], values[start]
    return values                          # at most n-1 swaps for the whole sort


print(selection_sort([5, 4, 3, 2, 1]))     # [1, 2, 3, 4, 5]
Why is it unstable?

Sort [3a, 3b, 1]. The first pass finds 1 and swaps it with the value in slot 0, which is 3a — so 3a is thrown to the far right, landing after 3b. Two equal keys changed their relative order, which is exactly what "unstable" means. Bubble sort never does this, because it only ever swaps neighbours.

Trace the passes

Step through it. the pair being compared  ·  a swap just happened  ·  the current minimum (selection sort)  ·  locked in its final position.

Try 1, 2, 3, 4, 5 on bubble sort to watch the early exit fire after a single pass — then try the same input on selection sort, which grinds through every pass regardless.
